# Travel Agent Prototype

זהו **Prototype / Proof of Concept** ראשוני לרעיון של סוכן AI לתכנון וליווי טיולים.

המטרה של הפרויקט כרגע היא **לא לבנות את האפליקציה הסופית**, אלא לבדוק בצורה מהירה שהחלקים הטכנולוגיים המרכזיים אפשריים: קבלת יעד מהמשתמש, מציאת מקומות אמיתיים, בניית מסלול בסיסי, חישוב מסלולי הליכה והצגת הכול על מפה.

---

## מה הפרוטוטייפ יודע לעשות כרגע?

המשתמש יכול:

- להקליד עיר, לדוגמה `Rome`, `Paris` או `Barcelona`.
- לבחור מספר ימים.
- לבחור קצב טיול: רגוע / מאוזן / עמוס.
- לבחור תחומי עניין בסיסיים.
- לקבל מקומות אמיתיים מתוך OpenStreetMap.
- לקבל חלוקה בסיסית של המקומות לימי טיול.
- לראות את סדר הפעילויות.
- לראות מסלול הליכה על מפה.
- לראות זמן ומרחק הליכה בין פעילויות.
- לנעול פעילות כדי לסמן שלא רוצים לשנות אותה.

> חשוב: זה עדיין Prototype. התקציב, מספר הנוסעים והטקסט החופשי עדיין לא משפיעים באמת על מנוע התכנון, ועדיין אין AI פעיל.

---

# הקבצים בפרויקט

## `app.py`

זהו **הקובץ הראשי של האפליקציה**.

הוא אחראי על:

- ממשק המשתמש של Streamlit.
- השאלון שמופיע בדפדפן.
- קבלת היעד וההעדפות.
- בניית המסלול הבסיסי.
- סידור הפעילויות.
- הצגת הימים.
- הצגת מפות.
- הצגת זמני ומרחקי הליכה.
- כפתורי נעילת הפעילויות.

אם רוצים לשנות את מה שהמשתמש רואה באפליקציה, ברוב המקרים מתחילים ב-`app.py`.

---

## `places.py`

הקובץ הזה אחראי על **קבלת מידע אמיתי על מקומות**.

כרגע הוא משתמש בשירותים של OpenStreetMap:

### Nominatim

משמש כדי להפוך שם של עיר לקואורדינטות.

לדוגמה:

```text
Rome
↓
Latitude: 41.893...
Longitude: 12.482...
```

### Overpass API

אחרי שאנחנו יודעים איפה העיר נמצאת, הקוד מחפש באזור:

- מוזיאונים
- אטרקציות
- גלריות
- פארקים

הקובץ מכיל גם כמה שרתי Overpass חלופיים, כדי שאם שרת אחד לא עובד המערכת תוכל לנסות שרת אחר.

---

## `routing.py`

הקובץ הזה אחראי על **מסלולי ההליכה**.

הוא מקבל סדרה של מקומות עם Latitude ו-Longitude ושולח אותם לשירות Routing.

הוא מחזיר:

- מסלול הליכה ברחובות.
- זמן הליכה.
- מרחק הליכה.
- מידע על הדרך בין כל שתי פעילויות.

לדוגמה:

```text
Museo di Roma
↓
6 דקות הליכה
450 מטר
↓
Pantheon
```

---

## `requirements.txt`

הקובץ הזה מכיל את ספריות Python שהפרויקט צריך.

במקום שכל אחד יתקין את הספריות ידנית, פשוט מריצים:

```bash

```

והכול מותקן אוטומטית.

# יצירת סביבת Python

מומלץ שכל אחד יעבוד עם Virtual Environment נפרד.

צור סביבה:

```bash

```

הפעל אותה ב-Windows:

```bash
.venv\Scripts\activate
```

אם הכול תקין, בתחילת שורת ה-CMD יופיע:

```text

```

```text
(.venv) C:\Users\...\travel-agent-prototype>
```

כאשר ה-Virtual Environment פעיל:

המטרה היא **למידה והוכחת היתכנות**.

אנחנו לא מניחים שהקוד הזה יהיה הקוד של המוצר הסופי.

הוא מאפשר לנו לבדוק מוקדם שאלות כמו:

- האם אפשר למצוא מקומות אמיתיים לפי יעד?

- איך מחשבים זמני הליכה?

- אילו חלקים חייבים להיות בקוד רגיל ואילו חלקים יתאימו ל-AI?

גם אם בעתיד נכתוב חלק גדול מהמערכת מחדש, הידע שמקבלים מה-Prototype עוזר לנו לקבל החלטות טובות יותר לפני פיתוח המוצר האמיתי.
